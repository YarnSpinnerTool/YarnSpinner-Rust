# ANTLR files

All files in this directory are autogenerated from the Yarn grammar by ANTLR
(via the `antlr4rust` tool) and then post-processed by the `generate_parser`
codegen step. **They are not edited by hand** — re-run the generator instead.

The grammars live in the `third-party/YarnSpinner` submodule, pinned to the
YarnSpinner release this crate targets. (In newer YarnSpinner versions they moved
into a `Grammars/` subdirectory; the generator handles both layouts.)

## Regenerating

1. Install a **Java 11+** runtime.
2. Download the ANTLR generator jar from
   [antlr4rust](https://github.com/antlr4rust/antlr4/releases) that matches the
   `antlr4rust` runtime version in `crates/compiler/Cargo.toml` (currently
   `0.5.x`, built against ANTLR 4.13 — `antlr4-4.13.3-SNAPSHOT-complete.jar`).
   Place it at `.antlr/` in the repo root, or point `ANTLR4RUST_JAR` at it.
3. Check out the submodules: `git submodule update --init --recursive`.
4. Run:

   ```bash
   cargo run -p yarnspinner_codegen --bin generate_parser
   ```

That runs the ANTLR tool and applies the deterministic fix-ups below. Each fix-up
asserts how many times its anchor appears in the freshly generated output, so if a
future `antlr4rust` release changes the generated code the step fails loudly
(rather than silently emitting broken or unpatched code).

## Automated fix-ups

These are applied by `crates/codegen/src/bin/generate_parser.rs`:

* Rename `YarnSpinnerParserParserContext` → `YarnSpinnerParserContext` (the
  generator emits the context type with a doubled `Parser` segment).
* Disambiguate `visitor.visit_node(self)` → `YarnSpinnerParserVisitor::visit_node(visitor, self)`
  in `NodeContext::accept`; the bare call resolves to the wrong `visit_node` and
  recurses forever (`node` is special in the ANTLR runtime).
* Inject a `new_with_text` constructor for `HashtagContextExt` (not emitted by
  ANTLR; mirrors a C# convenience used when synthesising hashtag nodes for line
  tagging). It must live in the generated module because it constructs the
  module-private `ph` field.
* Delete the generated-but-unused `yarnspinnerparserbaselistener.rs` and
  `yarnspinnerparserbasevisitor.rs`.

The generated `mod` declarations (with lint-allow attributes) live in the
hand-maintained `../generated.rs`, not here.

> Note: the `type_` field on `Declare_statementContextExt` is emitted as a valid
> Rust identifier by this generator, so the old "rename `type` → `declaration_type`"
> manual step is no longer needed; callers use `.type_` directly.
